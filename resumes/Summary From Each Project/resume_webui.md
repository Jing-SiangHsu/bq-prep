# web-ui — Resume Content

**Role:** Full-Stack Engineer (frontend lead across 5 hardware product lines + backend/gateway implementer for auth and security features)
**Stack:** AngularJS 1.x, TypeScript, Jade/Pug templates; Go (gRPC services + REST gateway, PAM integration via CGO)
**Scope:** 460 commits (402 frontend in `web-ui`, 58 backend in `intri-gateway`), ~123 GitHub issues, across 5 product-line frontend repos (OS2, OS3/OS4, OS5, OS6, Viewer) plus the shared backend gateway over ~1 year
**What it is:** The managed-network-switch web management UI and its backend gateway — configuration, monitoring, and security administration for industrial Ethernet switches, spanning SNMP, redundancy protocols, industrial fieldbus protocols, and compliance-grade security features. `intri-gateway` is the Go service both `web-ui` and the device CLI talk through: it terminates REST from the browser, proxies to internal gRPC "Core" services, and owns session/auth state.

> Honest framing: this is industrial-networking firmware UI/backend work, not AI/ML. What transfers is the shape of the engineering: integrating many independent third-party-style protocol "tools" behind one consistent interface, designing and implementing multi-step auth/security protocols end-to-end (not just the UI for them), building an event/notification subsystem from scratch, and a documented habit of root-causing bugs rather than patching symptoms — all directly relevant to building reliable agent/tool-orchestration systems and AI-product backends.

## Resume Bullets

- **Designed and implemented a full PAM-based multi-factor authentication (TOTP) system end-to-end, frontend through backend**: evaluated a Go PAM library, discovered it could intercept and discriminate the interactive PAM conversation itself (eliminating a legacy external C test binary entirely), and used that to design a non-breaking two-RPC login protocol — a password-only call that returns a distinguished "MFA required" result when the account's PAM stack expects a second factor, and a second password+TOTP call — shipped without altering the existing single-factor login contract for accounts that don't use MFA.
- **Built the Go PAM conversation-handler from scratch** (`github.com/msteinert/pam/v2`, via CGO): pattern-matches the live PAM prompt text to distinguish a password prompt from a TOTP prompt, tracks which factor was being verified when authentication failed, and threads a sentinel error up through the gRPC layer — replacing a previous design that shelled out to an external binary and parsed its stdout as JSON.
- **Led the backend implementation of IEC 62443-4-2 Security-Level-3 session controls** (~24 commits): per-user, per-interface (Web/SSH/Telnet/Console) concurrent-session tracking and enforcement, a new internal gRPC service so non-web login paths (SSH/Telnet) could enforce the same limit as the web gateway, forced session termination when an admin revokes interface access, and an audit-logging pipeline iteratively corrected to avoid double-logging and silent log-filter feedback loops.
- **Fixed a security-relevant data-corruption bug from a teammate's root-cause diagnosis**: a config-save pipeline was masking passwords for display *before* the final "read current config to persist" step ran, so saved config files on disk contained literal masked placeholders instead of the real encrypted secrets across five different config domains — relocated masking to the outermost gateway layer (mask only on the way out, restore the real value on save-back when the client echoes the placeholder unchanged) and fixed a related SSH-key-matching bug that broke under reordering by switching from index-based to fingerprint-based identity matching.
- **Led the frontend implementation of the IEC 62443-4-2 compliance initiative** spanning 15+ issues across two product lines: credential-encryption pipeline (client-side encryption before transmission, change-aware re-encryption to avoid double-hashing), SSH public-key management UI, and the MFA login UI built against the backend protocol above.
- **Designed and built a real-time notification subsystem from scratch** (~50 commits): persistent drawer + transient toast UI, hover-pause auto-dismiss, do-not-disturb state, bounded-memory ring buffer for the event queue — including evaluating and then deliberately reverting a third-party toast library mid-build once requirements diverged, in favor of a custom implementation.
- **Re-architected the core interface/identity data model** to support multi-unit stacked hardware configurations, replacing a single-device assumption with a unit-aware abstraction layer and a reusable UI directive pattern, then rolled it out across 30+ pages — tracked and executed as a deliberate, checklisted migration rather than ad hoc page-by-page patches.
- **Identified and fixed a recurring class of stale-reference bugs** in polling-driven UI state (object-identity tracking breaking under periodic data refresh) across three independent features, naming the pattern explicitly and applying the same index-based-tracking fix each time rather than treating each occurrence as a one-off.
- **Integrated 10+ distinct industrial communication protocols** (Modbus TCP/RTU, EtherNet/IP, PROFINET, TRDP/TTDP railway data protocols, G.8032 ring redundancy, MRP, gPTP/IEEE 802.1AS) into a single UI architecture, using a shared license/capability-gated navigation mechanism so optional hardware features could be added without per-feature special-casing.
- **Owned a build-pipeline performance problem** end-to-end: wrote a custom fail-fast replacement for a multi-process build tool that was silently swallowing worker failures, introduced an explicit model-allowlist to cut unnecessary asset processing, and iteratively resolved CI-environment issues until the pipeline was reliable across 4 product-line repos.
- **Practiced and documented root-cause-driven debugging as standard process** — consistently wrote "Root Cause / Solution / Side-Effects Analysis" writeups in issue threads, including cases requiring tracing a single user-facing symptom back through three unrelated components to find the true cause, and diagnosing a nil-pointer crash to an incompletely wired new gRPC service (client existed in the proto layer, but the gateway hadn't registered a concrete backing client for it).

## Supporting talking points (for interviews)

**MFA protocol design (strongest backend story):** I was handed "add TOTP-based MFA" with no existing protocol to plug into. My first instinct — evaluate a Go PAM library as a drop-in replacement for the existing single-factor PAM call — turned out to be insufficient on its own, since PAM's interactive conversation model doesn't map cleanly onto a two-page web login (password page, then TOTP page) without extra design. I re-tested the library and found it could expose the *individual PAM prompts* to my own code, which meant I could write a conversation handler that recognizes a TOTP prompt by its text and reports back specifically "this account needs a second factor" rather than a generic failure. That let me design a two-RPC split (password-only call, password+TOTP call) where the *existing* single-factor login contract for non-MFA accounts didn't change at all — a non-breaking protocol extension I designed and then implemented myself end-to-end, frontend and backend.

**Security bug with real consequences:** A config-save bug meant passwords written to disk were literally the masked placeholder string, not the real value — a genuinely bad bug (next reboot, those credentials would be unusable) caused by masking being applied too early in a multi-stage pipeline. Finding it required tracing the actual save pipeline stage-by-stage to see where "the value for display" and "the value for persistence" had been conflated, then moving the masking to the one layer where that distinction could be enforced correctly for every config domain at once instead of patching each domain separately.

**Pattern recognition across a legacy codebase:** Three separate bugs — in RMON row-expansion, DHCP tab-switching, and stacking interface visibility — turned out to be the same root cause (state tracked by object reference instead of stable index, broken by polling-driven object replacement). I named this pattern explicitly while fixing the second occurrence and proactively flagged it as likely present elsewhere, rather than waiting for it to be reported again.

**Protocol breadth:** Across the year I shipped UI for everything from SNMP-adjacent settings to real-time industrial protocols like TRDP (used in railway systems) and G.8032 ring redundancy — each required understanding the protocol's actual semantics (not just wiring a form) to get edge cases right, e.g. co-designing ring-port uniqueness validation rules with the backend owner.

**Why this maps to AI engineering:** Designing a PAM conversation handler that interprets live, semi-structured prompt text to drive control flow is structurally similar to building a tool/function-calling layer that has to interpret structured-but-variable responses and branch accordingly. The MFA protocol split is the same non-breaking-extension skill needed for multi-step agent or tool-calling protocols. Root-causing the password-masking bug to a pipeline-staging error is the same debugging discipline needed in multi-stage data/inference pipelines where "value for display" and "value for downstream processing" diverge. And integrating 10+ independent protocols behind one consistent, capability-gated interface mirrors integrating many tools/APIs into an agent framework with per-tool availability gating.
